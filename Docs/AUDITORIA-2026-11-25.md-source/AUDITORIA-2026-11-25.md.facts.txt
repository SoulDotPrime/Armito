# Armito

**Armito** é um projeto de tradução e compatibilidade de instruções
entre arquiteturas, concebido para permitir que software desenvolvido
para uma arquitetura de origem seja executado em uma arquitetura de
destino por meio de decodificação, representação intermediária e
tradução controlada.

O projeto é desenvolvido em C, com assembly quando necessário. Sua
arquitetura é modular: o `ArmitoBoot` prepara o ambiente, o `Core`
coordena os componentes e o `Decoder` interpreta blocos de instruções
para produzir uma representação intermediária universal.

> O objetivo do Armito é construir uma infraestrutura própria de
> tradução e compatibilidade, não apenas um tradutor isolado de
> instruções.

## Objetivos

-   Criar uma base de tradução entre arquiteturas, começando pelo fluxo
    ARM64 Apple → x86_64.
-   Separar inicialização, orquestração, decodificação, tradução e
    execução.
-   Desenvolver uma representação intermediária independente da
    arquitetura de origem e de destino.
-   Permitir expansão para diferentes CPUs, ambientes e caminhos de
    compatibilidade.
-   Manter o projeto modular, verificável e preparado para integração
    com o ArmitoBoot.

## Arquitetura em alto nível

``` text
ArmitoBoot
    |
    v
   Core
    |
    +---- Registry
    +---- Dependency
    +---- Init / Shutdown
    +---- Dispatch
    +---- Scheduler
    +---- IPC
    +---- Monitor
    +---- Diagnostics
    +---- Topology
    |
    v
  Decoder
    |
    v
 Universal IR
    |
    v
 Translator / Backend
    |
    v
 Target Architecture
```

A topologia acima representa a direção arquitetural pretendida. Nem
todos os componentes ou fluxos estão concluídos ou validados.

## Estado atual

O trabalho está concentrado na consolidação do `Core`. Já existem
subsistemas para configuração, registro de módulos, dependências,
inicialização, diagnóstico, despacho, monitoramento, topologia,
escalonamento, IPC e encerramento. A presença de código não significa,
por si só, que cada subsistema esteja auditado, testado ou pronto para
produção.

Consulte [STATUS.md](STATUS.md) para o estado de desenvolvimento e
[ROADMAP.md](ROADMAP.md) para as próximas etapas.

## Compatibilidade

A direção inicial é ARM64 Apple como origem e x86_64 como destino. O
suporte efetivo depende de decoder, IR, tradutor, backend e serviços de
plataforma compatíveis. Consulte [COMPATIBILITY.md](COMPATIBILITY.md).

## Princípios do projeto

-   C como linguagem principal.
-   Assembly apenas quando necessário e com escopo explícito.
-   Módulos com responsabilidades delimitadas.
-   O `Core` orquestra; não substitui a responsabilidade dos
    subsistemas.
-   `fail.c` é a autoridade de detecção de falhas.
-   Diagnósticos do Core apresentam e encaminham informações; não
    duplicam a detecção.
-   Mudanças devem ser verificáveis e documentadas.

# What is Armito?

## Definição

Armito é uma infraestrutura de tradução e compatibilidade entre
arquiteturas de processadores. Seu propósito é receber instruções ou
blocos de código de uma arquitetura de origem, compreender sua
semântica, convertê-los para uma representação intermediária e permitir
que componentes posteriores produzam uma forma executável na arquitetura
de destino.

A primeira direção de pesquisa estabelecida é **ARM64 Apple → x86_64**.
Essa direção inicial não limita a arquitetura final do projeto: o
desenho deve permitir outros pares de arquiteturas sem acoplar o núcleo
a um único processador.

## O problema que o Armito pretende resolver

Arquiteturas diferentes possuem conjuntos de instruções, convenções de
chamada, modelos de memória, registradores, exceções e interfaces de
sistema distintos. Executar software de uma arquitetura em outra exige
mais do que trocar códigos de operação.

Uma solução precisa tratar, conforme o escopo:

-   decodificação correta das instruções;
-   semântica e estado dos registradores;
-   flags e operações aritméticas;
-   memória, alinhamento e ordenação;
-   desvios, chamadas e retornos;
-   exceções e condições de falha;
-   convenções ABI;
-   chamadas de sistema e serviços de plataforma;
-   instruções privilegiadas e recursos específicos do hardware.

O Armito organiza essas responsabilidades em componentes independentes
para que possam ser desenvolvidas, verificadas e substituídas
separadamente.

## O que ele é

-   Um projeto de tradução entre arquiteturas.
-   Uma infraestrutura modular de compatibilidade.
-   Um sistema com decoder e representação intermediária.
-   Uma base extensível para backends de arquiteturas de destino.
-   Um ecossistema que inclui inicialização e orquestração próprias por
    meio do ArmitoBoot e do Core.

## O que ele não é

-   Não é apenas um desassemblador.
-   Não é apenas um emulador de CPU.
-   Não é, por si só, uma máquina virtual completa.
-   Não é um substituto automático de drivers, firmware, kernel ou
    serviços do sistema operacional.
-   Não deve ser descrito como compatibilidade universal já alcançada.

A tradução pode coexistir com emulação de partes do ambiente, serviços
de compatibilidade e execução nativa no destino. A escolha depende do
comportamento que precisa ser reproduzido.

## Modelo conceitual

1.  **Inicializar:** ArmitoBoot prepara o ambiente e transfere o
    controle ao Core.
2.  **Orquestrar:** Core valida e inicializa os módulos necessários.
3.  **Decodificar:** Decoder interpreta instruções em blocos ordenados.
4.  **Representar:** as instruções são convertidas para uma Universal
    IR.
5.  **Traduzir:** um tradutor/backend mapeia a IR para a arquitetura de
    destino.
6.  **Executar:** o código traduzido é executado sob os contratos de
    plataforma definidos.
7.  **Diagnosticar:** falhas são detectadas pela autoridade designada e
    apresentadas pelos mecanismos de diagnóstico.

## Direção de longo prazo

O objetivo é que Armito evolua de uma implementação inicial de tradução
ARM64 Apple → x86_64 para uma infraestrutura extensível, capaz de
suportar múltiplas arquiteturas e diferentes ambientes de execução. Isso
exige contratos estáveis entre módulos, testes semânticos e documentação
rigorosa.

## Critério de sucesso

O projeto só poderá afirmar suporte a uma combinação de arquiteturas
quando houver:

-   cobertura documentada das instruções suportadas;
-   testes de equivalência semântica;
-   tratamento definido de instruções não suportadas;
-   comportamento validado para memória, fluxo de controle e estado da
    CPU;
-   backend funcional na arquitetura de destino;
-   testes integrados no ambiente declarado como suportado.

# Armito Architecture

## 1. Visão geral

Armito é dividido em camadas para evitar que inicialização, coordenação,
decodificação e tradução fiquem acopladas.

``` text
+------------------------------+
|          ArmitoBoot          |
| Firmware / ambiente / handoff|
+---------------+--------------+
                |
                v
+------------------------------+
|             Core             |
| Lifecycle, registry, deps,   |
| dispatch, scheduler, IPC,     |
| monitor, diagnostics         |
+---------------+--------------+
                |
                v
+------------------------------+
|           Decoder            |
| Instruction stream -> IR     |
+---------------+--------------+
                |
                v
+------------------------------+
|          Universal IR        |
| Architecture-neutral model   |
+---------------+--------------+
                |
                v
+------------------------------+
| Translator / Target Backend  |
| IR -> target instructions    |
+---------------+--------------+
                |
                v
+------------------------------+
|       Execution Platform     |
+------------------------------+
```

Este é o modelo-alvo. O desenho não afirma que todas as camadas já
estejam implementadas.

## 2. ArmitoBoot

ArmitoBoot é o ponto de entrada e preparação do ambiente. Suas
responsabilidades previstas incluem:

-   identificar o ambiente de boot;
-   reunir informações de plataforma;
-   preparar os serviços necessários;
-   inicializar o Core;
-   entregar o contexto de boot ao Core;
-   transferir o fluxo sem invocar diretamente o Decoder.

O contrato exato entre ArmitoBoot e Core será definido antes da
integração final.

## 3. Core

Core é o orquestrador do runtime do Armito. Ele controla o ciclo de vida
dos módulos e a ordem em que os serviços são preparados e executados.

Core não deve assumir responsabilidades internas de módulos
especializados. Em particular, não deve duplicar o detector global de
falhas.

Consulte [CORE.md](CORE.md).

## 4. Decoder

Decoder recebe blocos de instruções da arquitetura de origem,
processa-os sequencialmente e produz Universal IR.

Responsabilidades esperadas:

-   validar entradas e limites do bloco;
-   identificar instruções;
-   decodificar campos e operandos;
-   preservar a ordem e o fluxo semântico;
-   emitir operações de IR;
-   reportar instruções inválidas ou não suportadas;
-   não executar diretamente código de destino.

O contrato de entrada e saída, o tratamento de instruções variáveis e a
política de blocos precisam ser especificados antes de declarar o
Decoder concluído.

## 5. Universal IR

A IR deve representar operações sem depender diretamente dos códigos de
operação de uma ISA específica. Deve contemplar, conforme a evolução do
projeto:

-   operações aritméticas e lógicas;
-   leitura e escrita de registradores virtuais;
-   acesso à memória;
-   comparações e flags;
-   desvios e blocos básicos;
-   chamadas e retornos;
-   conversões e extensões;
-   operações atômicas;
-   operações especiais ou intrínsecas;
-   metadados de origem e condições de validação.

A IR precisa ter regras formais de tipos, largura, efeitos colaterais e
semântica. Uma IR "universal" não deve apagar diferenças semânticas
entre arquiteturas.

## 6. Translator e backends

O tradutor converte IR para uma arquitetura de destino. Backends
separados permitem que o modelo intermediário permaneça independente da
ISA de destino.

Um backend precisa definir:

-   mapeamento de operações;
-   alocação de registradores;
-   convenções de chamada;
-   geração de desvios;
-   acessos à memória;
-   operações sem mapeamento direto;
-   alinhamento e requisitos de código;
-   validação do código emitido.

## 7. Serviços de plataforma

A execução real pode exigir camadas adicionais para ABI, chamadas de
sistema, bibliotecas, exceções, memória virtual e serviços do sistema
operacional. Essas funções não devem ser confundidas com a tradução de
instruções da CPU.

## 8. Fluxo de falhas

`fail.c` é a autoridade responsável por detectar falhas. Os componentes
podem retornar estados e fornecer contexto, mas não devem criar um
segundo sistema concorrente de detecção.

O Core Diagnostics atua como adaptador de apresentação e encaminhamento
para `Display.c` e `LogGen.c`.

## 9. Regras de dependência

-   ArmitoBoot inicializa o Core.
-   Core coordena os módulos.
-   ArmitoBoot não chama Decoder diretamente.
-   Decoder produz IR; não deve assumir as responsabilidades do backend.
-   Backends consomem IR e geram instruções de destino.
-   Falhas seguem a autoridade única definida em [FAILS.md](FAILS.md).

## 10. Evolução

A arquitetura deve ser consolidada por contratos e testes antes da
expansão para novos pares de ISA. Primeiro deve ser provado um caminho
vertical completo e verificável; depois, a cobertura deve crescer de
forma incremental.

# Core

## 1. Papel do Core

Core é o núcleo de orquestração do Armito. Ele gerencia o ciclo de vida
dos módulos, suas dependências, inicialização, execução coordenada,
monitoramento, comunicação e encerramento.

Core não é o Decoder e não deve conter a lógica específica de tradução
de instruções.

## 3. Responsabilidades

  Subsistema    Responsabilidade
  ------------- -------------------------------------------------------------
  Config        Configuração, limites, validação e bloqueio da configuração
  Init          Preparar, inicializar, iniciar e encerrar módulos
  Registry      Registrar módulos e manter seus estados
  Dependency    Registrar e resolver dependências
  Diagnostics   Encaminhar e apresentar informações de falhas
  Dispatch      Despachar chamadas para módulos
  Monitor       Expor estado e métricas de execução
  Topology      Construir e consultar a ordem topológica
  Scheduler     Executar tarefas cooperativas por prioridade
  IPC           Trocar mensagens entre módulos
  Shutdown      Coordenar encerramento e reset do Core

## 4. Tipos e estados

`CoreTypes.h` define os estados gerais do Core, estados dos módulos,
prioridades e identificadores.

Estados de módulo atualmente previstos:

-   `ARMITO_MODULE_UNREGISTERED`
-   `ARMITO_MODULE_REGISTERED`
-   `ARMITO_MODULE_INITIALIZING`
-   `ARMITO_MODULE_INITIALIZED`
-   `ARMITO_MODULE_RUNNING`
-   `ARMITO_MODULE_STOPPED`
-   `ARMITO_MODULE_INITIALIZATION_FAILED`
-   `ARMITO_MODULE_EXECUTION_FAILED`

O significado de cada transição deve ser validado na auditoria do Init e
do Registry.

## 5. Ciclo de vida pretendido

1.  Inicializar Config.
2.  Preparar Registry e Dependency.
3.  Inicializar os serviços-base do Core.
4.  Registrar módulos.
5.  Construir a topologia a partir das dependências.
6.  Inicializar subsistemas opcionais habilitados.
7.  Bloquear a configuração para impedir alterações durante a execução.
8.  Inicializar módulos na ordem resolvida.
9.  Iniciar módulos.
10. Em encerramento, parar módulos na ordem inversa e liberar
    subsistemas.

A sequência exata e o rollback em caso de falha ainda precisam ser
comprovados por testes.

## 6. API pública conhecida

A interface pública principal em `Core/Includes/Core.h` contém:

-   `ArmitoCoreRegisterModule`
-   `ArmitoCoreInitialize`
-   `ArmitoCoreStart`
-   `ArmitoCoreShutdown`
-   `ArmitoCoreGetModuleState`

A API pública ainda precisa ser auditada. A operação de adicionar
dependências, por exemplo, existe na interface interna do subsistema
Dependency, mas precisa de uma decisão explícita sobre sua exposição
pela API pública.

## 7. Configuração atual

A configuração inclui limites para:

-   módulos: máximo estrutural 64;
-   dependências por módulo: máximo estrutural 16;
-   tarefas: máximo estrutural 64;
-   mensagens IPC: máximo estrutural 64;
-   payload IPC: máximo estrutural 256 bytes.

Também há habilitação para Scheduler, IPC, Monitor e Diagnostics. Esses
limites são limites de implementação conhecidos, não uma garantia de
desempenho ou adequação a qualquer plataforma.

## 8. Limitações e pontos de auditoria

-   Rollback parcial de inicialização ainda precisa ser corrigido.
-   Falha durante `initialize()` precisa ter política definida para
    recursos parcialmente alocados.
-   Falha durante `start()` precisa deixar os módulos em estado
    consistente.
-   Shutdown e reinicialização precisam ser testados em ciclos
    repetidos.
-   O encerramento da configuração deve ocorrer depois dos demais
    subsistemas.
-   Registry e Dependency precisam deixar de depender implicitamente de
    IDs sequenciais se o desenho futuro permitir IDs esparsos.
-   Scheduler é cooperativo, sem preempção ou sincronização concorrente.
-   IPC usa fila fixa e ainda precisa de abstração de memória adequada
    ao ambiente freestanding.
-   IPC precisa de política para permissões, estado dos módulos e
    sincronização.
-   Monitor precisa distinguir módulos obrigatórios e opcionais.
-   Diagnostics precisa ser conectado ao `fail.c`, `Display.c` e
    `LogGen.c`.

## 9. Regra de falhas

Core não detecta nem classifica independentemente falhas globais.
`fail.c` é a autoridade de detecção. Core recebe o resultado e encaminha
a apresentação.

## 10. Critério de conclusão do Core

Core só deve ser considerado consolidado quando: - todos os subsistemas
tiverem contratos e estados definidos; - inicialização e rollback forem
determinísticos; - shutdown e reinicialização forem seguros; -
dependências forem resolvidas e validadas; - APIs públicas e internas
estiverem documentadas; - testes unitários e integrados cobrirem os
caminhos de sucesso e falha; - o build funcionar no ambiente de destino
declarado.

########## Docs/DECISIONS.md ##########
# Architectural Decisions

Este documento registra decisões estabelecidas para orientar o
desenvolvimento. Uma decisão só deve ser alterada mediante revisão
explícita e atualização deste arquivo.

## D-001 --- Linguagem principal

**Decisão:** C é a linguagem principal do Armito. Assembly pode ser
usado quando necessário.

**Motivo:** controle de baixo nível, integração com firmware e
previsibilidade em ambientes de sistema.

## D-002 --- Rust fora do escopo

**Decisão:** Rust não será usado na implementação atual do Armito.

## D-003 --- Core como orquestrador

**Decisão:** ArmitoBoot inicializa e transfere o controle ao Core. Core
coordena módulos e subsistemas.

**Consequência:** ArmitoBoot não chama Decoder diretamente.

## D-004 --- Decoder separado

**Decisão:** Decoder recebe blocos de instruções, decodifica
sequencialmente e produz Universal IR.

**Consequência:** Decoder não deve misturar decodificação com geração de
código de destino.

## D-005 --- Universal IR

**Decisão:** usar uma representação intermediária entre ISA de origem e
backend de destino.

**Consequência:** a IR deve preservar semântica, tipos, larguras e
efeitos colaterais, não apenas nomes genéricos de operações.

## D-006 --- Detector único de falhas

**Decisão:** `fail.c` é a autoridade responsável por detectar qualquer
falha.

**Consequência:** Core Diagnostics apresenta e encaminha; não duplica a
detecção.

## D-007 --- Saídas de diagnóstico separadas

**Decisão:** `Display.c` cuida da apresentação visual e `LogGen.c` do
registro em log.

## D-008 --- Compatibilidade de boot por caminhos

**Decisão:** considerar caminhos distintos para UEFI nativo, UEFI+CSM e
Legacy BIOS puro.

**Consequência:** Legacy BIOS puro exige estágio de entrada próprio; um
binário EFI isolado não cobre esse caminho.

## D-009 --- Desenvolvimento incremental

**Decisão:** concluir e auditar o Core antes da integração com Decoder e
ArmitoBoot.

## D-010 --- Arquivos completos nas alterações

**Decisão de fluxo de trabalho:** alterações de código devem ser
apresentadas como arquivos completos, com caminho explícito.

## D-011 --- Código sem comentários

**Decisão de estilo:** não inserir comentários dentro do código
fornecido.

## D-012 --- Uma alteração por vez

**Decisão de fluxo de trabalho:** apresentar uma alteração por etapa e
aguardar a confirmação do usuário antes de avançar.

## D-013 --- Estado não presumido

**Decisão:** código escrito não deve ser tratado como funcionalidade
validada sem compilação e teste. Documentação deve distinguir
implementado, integrado e validado.

## Processo de alteração

Para alterar uma decisão: 1. identificar o número da decisão; 2.
explicar o motivo da revisão; 3. registrar a nova decisão e suas
consequências; 4. atualizar documentos afetados; 5. ajustar o roadmap e
o status.

########## Docs/COMPATIBILITY.md ##########
# Compatibility

## 1. Escopo

Este documento separa compatibilidade de arquitetura de CPU de
compatibilidade de firmware e plataforma. São problemas diferentes e
precisam ser validados separadamente.

## 2. Direção inicial de ISA

  Papel                         Arquitetura inicial
  ----------------------------- ------------------------------------------------
  Origem                        ARM64 / AArch64, com foco no ecossistema Apple
  Destino                       x86_64
  Representação intermediária   Universal IR independente de ISA

A direção ARM64 Apple → x86_64 é o objetivo inicial de pesquisa. Isso
não significa que toda instrução ARM64, toda extensão Apple ou qualquer
aplicação Apple já seja suportada.

## 3. Níveis de compatibilidade

### Nível A --- Decodificação

O Decoder reconhece instruções e produz uma representação estruturada.
Isso não basta para executar software.

### Nível B --- Equivalência semântica

As operações da IR preservam os efeitos da instrução de origem,
incluindo largura, flags, memória e fluxo de controle.

### Nível C --- Geração de código

Um backend gera código válido para a arquitetura de destino.

### Nível D --- Ambiente de execução

Convenções de chamada, bibliotecas, chamadas de sistema, exceções e
serviços necessários são tratados.

### Nível E --- Aplicação

Uma aplicação real é executada e validada no ambiente de destino.

Uma declaração de suporte deve indicar explicitamente até qual nível foi
validada.

## 4. UEFI

O caminho UEFI é o caminho prioritário para a integração inicial com
ArmitoBoot.

Requisitos a validar: - arquitetura do binário EFI; - protocolos
disponíveis; - alocação e mapa de memória; - serviços de console e
saída; - GOP quando disponível; - transição correta do ambiente de
boot; - handoff de contexto entre ArmitoBoot e Core.

A presença de UEFI não garante que GOP ou todos os protocolos opcionais
estejam disponíveis.

## 5. UEFI com CSM

CSM é uma camada de compatibilidade Legacy oferecida por determinados
firmwares UEFI. Sua disponibilidade e seus recursos variam por firmware
e configuração.

Armito pode prever caminhos separados para: - UEFI nativo; - UEFI com
CSM habilitado; - Legacy BIOS puro.

O caminho UEFI+CSM deve tratar a possibilidade de GOP ausente e de
serviços UEFI limitados. A implementação não deve presumir que todos os
recursos do caminho UEFI nativo estarão presentes.

## 6. Legacy BIOS puro

Um executável EFI não inicializa diretamente em um ambiente Legacy BIOS
puro. Para suportá-lo, ArmitoBoot precisará de um estágio de entrada
compatível com BIOS, normalmente em código de 16 bits, que prepare o
ambiente e transfira o controle para uma etapa posterior.

Esse caminho exige desenvolvimento e testes próprios. Não deve ser
anunciado como suportado apenas porque o projeto compila para x86_64.

## 7. Compatibilidade de hardware

Compatibilidade com uma ISA não implica compatibilidade com qualquer
hardware que implemente essa ISA. Extensões de CPU, recursos opcionais,
instruções privilegiadas e características de memória precisam ser
detectados e tratados.

## 8. Política para instruções não suportadas

Cada instrução deve ter um dos seguintes resultados documentados: -
traduzida diretamente; - traduzida por sequência equivalente; -
encaminhada a um helper ou mecanismo de emulação; - rejeitada de forma
controlada como não suportada.

Nunca se deve emitir código aproximado sem preservar a semântica.

## 9. Matriz de status

  Área                      Direção          Estado
  ------------------------- ---------------- ------------------------------------------
  ARM64 Apple como origem   Inicial          Planejado / em pesquisa
  x86_64 como destino       Inicial          Planejado / em pesquisa
  Universal IR              Camada central   Em definição
  UEFI                      Boot             Caminho prioritário, integração pendente
  UEFI + CSM                Boot             Possibilidade arquitetural, não validada
  Legacy BIOS puro          Boot             Exige estágio próprio, não implementado
  Outros pares de ISA       Expansão         Futuro

Atualize esta matriz somente com base em testes reproduzíveis.

# Failure Model

## 1. Autoridade única

`fail.c` é a autoridade responsável por detectar falhas em Armito.

Essa decisão evita que Core, Decoder, ArmitoBoot e outros componentes
mantenham detectores paralelos com regras divergentes.

## 2. Separação de responsabilidades

  -----------------------------------------------------------------------
  Componente                          Responsabilidade
  ----------------------------------- -----------------------------------
  `fail.c`                            Detectar e determinar que uma falha
                                      ocorreu

  Core Diagnostics                    Receber, encaminhar e apresentar
                                      informações da falha

  `Display.c`                         Exibir a informação quando o
                                      dispositivo de saída estiver
                                      disponível

  `LogGen.c`                          Registrar a informação no mecanismo
                                      de log

  Core                                Coordenar o fluxo e o encerramento
                                      seguro quando necessário

  Subsistema de origem                Retornar estado e contexto
                                      suficientes para a autoridade de
                                      falhas
  -----------------------------------------------------------------------

Core Diagnostics não deve reimplementar a detecção nem competir com
`fail.c`.

## 3. Fluxo conceitual

``` text
Subsystem / ArmitoBoot / Decoder
              |
              v
           fail.c
              |
              v
       Failure information
              |
        +-----+-----+
        |           |
        v           v
    Display.c    LogGen.c
        ^           ^
        +-----+-----+
              |
       Core Diagnostics
       (adapter / routing)
```

O fluxo exato de chamadas deverá respeitar as interfaces reais de
`fail.c`, `Display.c` e `LogGen.c`. O diagrama representa
responsabilidades, não uma API já implementada.

## 4. Dados de uma falha

A estrutura de informação de falha deve permitir, conforme aplicável: -
identificador ou código; - severidade; - componente de origem; - etapa
do ciclo de vida; - endereço ou contexto técnico, se seguro e
disponível; - descrição curta; - estado recuperável ou fatal; - ação
tomada.

Não incluir dados não inicializados ou ponteiros cujo tempo de vida não
esteja garantido.

## 5. Severidade e resposta

A política de severidade deve distinguir pelo menos: - informativa; -
aviso; - erro recuperável; - erro fatal.

A classificação final deve pertencer ao contrato do sistema de falhas,
não ser reinventada por cada subsistema.

## 6. Falha de apresentação

A ausência de Display ou de um dispositivo gráfico não pode impedir o
registro da falha. Da mesma forma, falha no logger não deve provocar
recursão infinita no próprio sistema de falhas.

O sistema deve definir fallback seguro, por exemplo: - log serial,
quando disponível; - buffer de diagnóstico em memória previamente
reservado; - encerramento controlado, quando não houver canal confiável.

Esses fallbacks são requisitos de projeto a implementar e validar.

## 7. Recursão e falhas secundárias

O tratamento de uma falha pode falhar. O mecanismo precisa impedir: -
reentrada infinita; - alocação dinâmica não segura durante falha; -
dependência circular entre fail, Display e LogGen; - perda da falha
original por uma falha secundária.

## 8. Regras obrigatórias

1.  `fail.c` permanece como detector único.
2.  Core Diagnostics apenas instrumentaliza apresentação e
    encaminhamento.
3.  Display e LogGen não assumem detecção global.
4.  A falha original deve ser preservada.
5.  Falhas durante boot devem ter caminho mínimo de diagnóstico.
6.  Ausência de GOP não pode ser tratada automaticamente como ausência
    de qualquer saída.
7.  O sistema deve conseguir encerrar com segurança quando a recuperação
    não for possível.

## 9. Integração pendente

-   Mapear a API real de `fail.c`.
-   Mapear a API real de `Display.c`.
-   Mapear a API real de `LogGen.c`.
-   Definir estrutura comum de falha.
-   Implementar adaptador no Core Diagnostics.
-   Testar falhas antes e depois da inicialização do Core.
-   Testar ausência de display, falha de log e falha durante o próprio
    diagnóstico.

**Projeto:** Armito\
**Responsável:** SoulDotPrime\
**Documento:** Especificação geral, arquitetura, estado atual e roadmap\
**Escopo deste documento:** consolidar o que foi definido nas conversas

## 1. O que é o Armito

Armito é um projeto de tradução e compatibilidade entre arquiteturas de
processadores. Seu objetivo é criar uma infraestrutura capaz de receber
instruções de uma arquitetura de origem, interpretá-las, convertê-las
para uma representação intermediária universal e, posteriormente,
entregar essa representação a um componente responsável por produzir ou
executar operações compatíveis com a arquitetura de destino.

A primeira direção de desenvolvimento considerada é **ARM64 para
x86_64**, com atenção especial ao ecossistema Apple Silicon. Entretanto,
a arquitetura do projeto não deve ficar presa a essa combinação. O
objetivo de longo prazo é permitir diferentes combinações de
arquiteturas de origem e destino sem precisar reescrever todo o sistema
para cada par.

Em vez de construir um tradutor monolítico, Armito está sendo organizado
como uma infraestrutura modular. Cada componente possui uma
responsabilidade delimitada e se comunica por contratos definidos pelo
Core.

### 1.1 Visão central

O fluxo conceitual é:

1.  ArmitoBoot prepara o ambiente e inicia o Armito.
2.  ArmitoBoot transfere o controle para o Core.
3.  Core organiza os módulos, valida dependências e controla o ciclo de
    vida.
4.  Core aciona o Decoder no momento apropriado.
5.  Decoder interpreta sequencialmente os blocos de instruções da
    arquitetura de origem.
6.  Decoder produz uma representação intermediária universal, o
    **Universal IR**.
7.  A representação intermediária é encaminhada ao componente de
    tradução/execução de destino, incluindo a infraestrutura CPUToCPU.
8.  O resultado é preparado para a arquitetura de destino.

O Core é o orquestrador. O Decoder não deve ser chamado diretamente por
ArmitoBoot: **ArmitoBoot chama o Core, e o Core decide quando e como
chamar o Decoder.**

### 1.2 O que Armito pretende ser

Armito pretende ser:

-   Uma infraestrutura de tradução entre arquiteturas.
-   Um sistema modular, extensível e independente de um único par de
    arquiteturas.
-   Uma camada de abstração entre decodificação, representação
    intermediária e destino.
-   Uma base para compatibilidade de instruções e operações entre CPUs
    diferentes.
-   Um projeto que possa evoluir de uma primeira tradução ARM64 → x86_64
    para múltiplos alvos.
-   Um componente integrável ao fluxo de inicialização do ArmitoBoot.

### 1.3 O que Armito não deve ser

Armito não deve se tornar:

-   Um Decoder monolítico que contenha toda a lógica de tradução.
-   Um sistema em que ArmitoBoot conheça e controle diretamente cada
    subsistema.
-   Uma implementação limitada permanentemente a ARM64 e x86_64.
-   Um sistema em que cada Decoder produza uma saída exclusiva e
    incompatível com os demais.
-   Um sistema que duplique a detecção de falhas em vários módulos.

------------------------------------------------------------------------

## 2. Princípios de arquitetura

### 2.1 Modularidade

Cada subsistema deve ter uma responsabilidade explícita, uma API
definida e dependências controladas.

### 2.2 Representação intermediária universal

O Universal IR é o contrato central entre os componentes que interpretam
arquiteturas de origem e os componentes que traduzem ou executam
operações para arquiteturas de destino.

A intenção é que diferentes Decoders possam produzir o mesmo formato
intermediário e que diferentes backends possam consumi-lo. Assim, a
combinação de uma origem e um destino não exige necessariamente um
tradutor inteiramente independente.

O formato final do IR ainda precisa ser especificado. Não se deve
considerar sua semântica, codificação binária, modelo de registradores
ou regras de memória como concluídos antes dessa especificação.

### 2.3 Separação entre origem e destino

O Decoder deve conhecer as regras necessárias para interpretar a
arquitetura de origem. A tradução para uma arquitetura de destino deve
pertencer aos componentes responsáveis pelo backend e pela
infraestrutura CPUToCPU.

### 2.4 Orquestração centralizada

Core controla o ciclo de vida e a execução dos módulos. Os módulos não
devem iniciar uns aos outros de maneira arbitrária.

### 2.5 Falhas com autoridade única

`fail.c` é o responsável por detectar falhas. Core não deve duplicar
essa detecção nem criar uma segunda classificação concorrente.

Core apenas instrumentaliza a apresentação e o encaminhamento das
informações:

-   `Display.c`: apresentação visual.
-   `LogGen.c`: geração e registro de logs.
-   `Core/Diagnostics`: adaptação das informações de falha para os
    mecanismos de exibição e registro.

### 2.6 Portabilidade

O projeto deve evitar dependências acidentais do ambiente de
desenvolvimento. O Core precisa poder evoluir para um ambiente
freestanding/UEFI, com abstrações próprias para memória, serviços e
recursos de plataforma.

### 2.7 Código e manutenção

Convenções de desenvolvimento estabelecidas:

-   Linguagem principal: C.
-   Assembly pode ser utilizado quando necessário.
-   Rust não faz parte da implementação planejada.
-   Alterações devem ser entregues como arquivos completos, não como
    patches parciais.
-   Cada alteração deve indicar o caminho exato do arquivo.
-   Não inserir comentários dentro do código-fonte.
-   Desenvolver uma alteração por vez e confirmar sua aplicação antes de
    avançar.

------------------------------------------------------------------------

## 3. Arquitetura geral

A arquitetura lógica pode ser dividida em quatro grandes áreas.

### 3.1 Inicialização

Responsável por preparar o ambiente de execução e transferir o controle
para o Core.

Componente principal: **ArmitoBoot**.

### 3.2 Orquestração

Responsável por inicializar, registrar, organizar, executar, monitorar e
encerrar os módulos.

Componente principal: **Core**.

### 3.3 Tradução

Responsável por interpretar instruções da origem, produzir o Universal
IR e preparar operações para o destino.

Componentes centrais:

-   Decoder.
-   Universal IR.
-   CPUToCPU.
-   Adaptadores de arquitetura de origem.
-   Backends de arquitetura de destino.

### 3.4 Plataforma e integração

Responsável por fornecer os serviços de baixo nível necessários ao
funcionamento do sistema:

-   Memória.
-   Diagnósticos.
-   Logs.
-   Exibição.
-   Serviços de boot.
-   Interfaces específicas de plataforma.

-   Gerenciar dependências.

-   Inicializar e iniciar módulos.
-   Despachar operações.
-   Coordenar tarefas.
-   Permitir comunicação entre módulos.
-   Monitorar estados.
-   Apresentar diagnósticos recebidos de `fail.c`.
-   Encerrar o sistema de forma ordenada.

### 6.3 Pontos técnicos conhecidos que ainda precisam de auditoria

-   Registry copia o descritor do módulo, mas o campo `name` é uma

-   Dependency pressupõe IDs sequenciais em algumas operações. Essa

-   Scheduler mantém tarefas concluídas ou falhas registradas; ainda não

    ser estabelecidos.

## 7. Decoder

Decoder é o componente que interpreta instruções da arquitetura de
origem. Ele será acionado pelo Core, e não diretamente por ArmitoBoot.

### 7.1 Responsabilidades previstas

-   Receber blocos ou sequências de instruções.
-   Identificar a arquitetura de origem.
-   Interpretar instruções sequencialmente.
-   Validar os dados de entrada.
-   Decodificar instruções e operandos.
-   Identificar operações, registradores, memória e fluxo de controle.
-   Produzir instruções no Universal IR.
-   Reportar erros de decodificação ao mecanismo central de falhas.
-   Entregar o resultado ao próximo estágio por meio de uma interface
    definida.

### 7.2 Regra de independência

O Decoder não deve produzir diretamente código específico de uma única
arquitetura de destino. Sua saída primária é o Universal IR.

### 7.3 Decoders por arquitetura

A arquitetura deve permitir implementações específicas, por exemplo:

-   Decoder ARM64.
-   Decoder x86_64.
-   Outros decoders futuros.

Todos devem obedecer ao contrato comum de saída.

### 7.4 Itens ainda a especificar

-   Formato de entrada.
-   Identificação da arquitetura de origem.
-   Modelo de contexto de decodificação.
-   Representação de instruções inválidas ou não suportadas.
-   Tratamento de instruções privilegiadas.
-   Tratamento de exceções e condições especiais.
-   Regras de leitura de blocos e limites de memória.
-   Contrato de saída para o Universal IR.

------------------------------------------------------------------------

## 8. Universal IR

O Universal IR é a representação intermediária comum do Armito. É um dos
elementos mais importantes para a independência entre arquiteturas.

### 8.1 Objetivo

Permitir que um Decoder produza uma representação que possa ser
consumida por diferentes backends, sem que o Decoder precise conhecer
todos os destinos possíveis.

### 8.2 Requisitos arquiteturais

O IR deverá representar, no mínimo, conceitos como:

-   Operações aritméticas e lógicas.
-   Movimento de dados.
-   Operações de memória.
-   Registradores abstratos e mapeamento de registradores.
-   Comparações e condições.
-   Saltos e fluxo de controle.
-   Chamadas e retornos.
-   Conversões e extensões de dados.
-   Operações vetoriais, quando suportadas.
-   Barreiras e operações de sincronização.
-   Operações não suportadas ou que exijam tratamento especial.

A lista é uma base de requisitos, não uma especificação final.

### 8.3 Decisões ainda pendentes

-   Modelo SSA ou outro modelo de temporários.
-   Tipagem dos operandos.
-   Representação de flags e condições.
-   Modelo de memória e endianness.
-   Representação de exceções.

## 14. Critérios de conclusão

O Armito não deve ser considerado integrado apenas porque compila. A
conclusão precisa ser demonstrada por testes em cada camada.

### 14.1 Core concluído

-   Todos os subsistemas possuem contratos definidos.
-   Inicialização e encerramento são previsíveis.
-   Falhas parciais não deixam o Core em estado inconsistente.
-   Dependências são resolvidas corretamente.
-   Módulos opcionais são tratados corretamente.
-   Testes automatizados cobrem estados válidos e inválidos.
-   O Core compila no ambiente-alvo.

### 14.2 Decoder concluído para uma arquitetura

-   Recebe entrada válida e delimitada.
-   Decodifica instruções suportadas.
-   Rejeita ou sinaliza instruções inválidas.
-   Produz Universal IR válido.
-   Possui testes de conformidade.

### 14.3 Backend concluído para um destino

-   Consome Universal IR validado.
-   Traduz operações suportadas.
-   Sinaliza operações não suportadas.
-   Mantém semântica funcional nas operações cobertas.
-   Possui testes comparativos.

### 14.4 Integração final concluída

-   ArmitoBoot inicia o Core.
-   Core controla os módulos.
-   Core aciona Decoder.
-   Decoder produz IR.
-   CPUToCPU recebe o IR.
-   O backend de destino processa as operações.
-   Diagnósticos e logs funcionam nos caminhos de sucesso e falha.
-   O ciclo completo é repetível e testado.

## 15. Registro de decisões e regras permanentes

1.  O projeto é chamado **Armito**.
2.  O responsável pelo projeto, nos contextos do ecossistema, é
    **SoulDotPrime**.
3.  A linguagem principal é C; Assembly pode ser usado quando
    necessário.
4.  Rust está fora do escopo atual.
5.  Core é o orquestrador central.
6.  ArmitoBoot chama Core; não chama Decoder diretamente.
7.  Core decide quando o Decoder entra em ação.
8.  Decoder trabalha com instruções da arquitetura de origem.
9.  Decoder entrega Universal IR, não código específico de um destino.
10. CPUToCPU e os backends cuidam da adaptação ao destino.
11. `fail.c` é a autoridade de detecção de falhas.
12. Core apenas instrumentaliza a apresentação e o registro das falhas.
13. `Display.c` é o caminho de apresentação visual.
14. `LogGen.c` é o caminho de geração de logs.
15. O suporte a Legacy BIOS exige um estágio próprio; um binário EFI não
    é suficiente.
16. A arquitetura deve permitir múltiplas origens e múltiplos destinos.
17. Alterações de código devem ser fornecidas como arquivos completos.
18. Cada alteração deve informar o caminho exato do arquivo.
19. Não inserir comentários dentro do código-fonte.
20. O desenvolvimento deve avançar em etapas pequenas, com confirmação
    antes da próxima alteração.

## 16. Como manter este documento

Este arquivo é a referência mestre do projeto, mas não substitui os
contratos técnicos individuais de cada módulo.

A cada avanço relevante:

1.  Atualizar o estado do roadmap.
2.  Registrar decisões arquiteturais novas.
3.  Atualizar a topologia se arquivos ou subsistemas mudarem.
4.  Registrar limitações conhecidas.
5.  Diferenciar claramente o que está implementado, o que foi testado e
    o que está apenas planejado.
6.  Não marcar uma etapa como concluída somente porque o código foi
    escrito; exigir confirmação de aplicação e, quando aplicável, teste.

**Regra de rastreabilidade:** implementação, validação e integração são
estados diferentes. Um componente pode estar implementado sem estar
validado, e validado isoladamente sem estar integrado ao fluxo completo
do Armito.

-   Falha de inicialização.
-   Falha de execução.

-   Operação não suportada.

## 7. Decoder

Decoder é o componente que interpreta instruções da arquitetura de
origem. Ele será acionado pelo Core, e não diretamente por ArmitoBoot.

### 7.1 Responsabilidades previstas

-   Receber blocos ou sequências de instruções.
-   Identificar a arquitetura de origem.
-   Interpretar instruções sequencialmente.
-   Validar os dados de entrada.
-   Decodificar instruções e operandos.
-   Identificar operações, registradores, memória e fluxo de controle.
-   Produzir instruções no Universal IR.
-   Reportar erros de decodificação ao mecanismo central de falhas.
-   Entregar o resultado ao próximo estágio por meio de uma interface
    definida.

### 7.2 Regra de independência

O Decoder não deve produzir diretamente código específico de uma única
arquitetura de destino. Sua saída primária é o Universal IR.

### 7.3 Decoders por arquitetura

A arquitetura deve permitir implementações específicas, por exemplo:

-   Decoder ARM64.
-   Decoder x86_64.
-   Outros decoders futuros.

Todos devem obedecer ao contrato comum de saída.

### 7.4 Itens ainda a especificar

-   Formato de entrada.
-   Identificação da arquitetura de origem.
-   Modelo de contexto de decodificação.
-   Representação de instruções inválidas ou não suportadas.
-   Tratamento de instruções privilegiadas.
-   Tratamento de exceções e condições especiais.
-   Regras de leitura de blocos e limites de memória.
-   Contrato de saída para o Universal IR.

## 8. Universal IR

O Universal IR é a representação intermediária comum do Armito. É um dos
elementos mais importantes para a independência entre arquiteturas.

### 8.1 Objetivo

Permitir que um Decoder produza uma representação que possa ser
consumida por diferentes backends, sem que o Decoder precise conhecer
todos os destinos possíveis.

### 8.2 Requisitos arquiteturais

O IR deverá representar, no mínimo, conceitos como:

-   Operações aritméticas e lógicas.
-   Movimento de dados.
-   Operações de memória.
-   Registradores abstratos e mapeamento de registradores.
-   Comparações e condições.
-   Saltos e fluxo de controle.
-   Chamadas e retornos.
-   Conversões e extensões de dados.
-   Operações vetoriais, quando suportadas.
-   Barreiras e operações de sincronização.
-   Operações não suportadas ou que exijam tratamento especial.

A lista é uma base de requisitos, não uma especificação final.

### 8.3 Decisões ainda pendentes

-   Modelo SSA ou outro modelo de temporários.
-   Tipagem dos operandos.
-   Representação de flags e condições.
-   Modelo de memória e endianness.
-   Representação de exceções.
-   Metadados de origem.
-   Versão e compatibilidade do IR.
-   Formato em memória e eventual formato serializado.
-   Estratégia de validação do IR.

## 9. CPUToCPU e backends

CPUToCPU faz parte da infraestrutura que conecta a representação
intermediária à arquitetura de destino.

### 9.1 Responsabilidade pretendida

-   Consumir o Universal IR.
-   Aplicar regras específicas da arquitetura de destino.
-   Resolver o mapeamento de registradores.
-   Resolver operações e convenções de chamada.
-   Gerar operações ou código compatível com o destino.
-   Tratar operações sem equivalência direta.
-   Reportar operações não suportadas.

### 9.2 Arquitetura de destino

A primeira meta de compatibilidade considerada é x86_64. A implementação
deve evitar que o backend x86_64 determine o formato interno do Decoder
ou do IR.

### 9.3 Extensibilidade

O projeto deve permitir adicionar outros backends sem alterar o contrato
central do Decoder.

## 10. ArmitoBoot e relação com Core

ArmitoBoot é o responsável pela etapa de inicialização e preparação do
ambiente. Core é o responsável pela orquestração do Armito depois que
recebe o controle.

### 10.1 Divisão de responsabilidades

  -----------------------------------------------------------------------
  ArmitoBoot                          Core
  ----------------------------------- -----------------------------------
  Prepara o ambiente de boot          Gerencia o ambiente interno do
                                      Armito

  Obtém e organiza os dados iniciais  Registra e organiza módulos

  Inicializa os serviços necessários  Inicializa os subsistemas e módulos
  ao Core                             

  Invoca a API pública do Core        Controla o ciclo de vida

  Entrega o controle ao Core          Decide quando acionar o Decoder

  Trata a transição de boot           Coordena execução, comunicação e
                                      encerramento
  -----------------------------------------------------------------------

### 10.2 Regra de integração

ArmitoBoot não deve chamar Decoder diretamente. A integração deve
ocorrer por meio de um contrato público e estável entre ArmitoBoot e
Core.

### 10.3 Compatibilidade de boot

Foi discutida a possibilidade de suportar diferentes caminhos de
inicialização:

-   UEFI nativo.
-   UEFI com CSM.
-   Legacy BIOS, mediante um estágio de boot específico.

Um executável EFI não é, por si só, um executável de boot para BIOS
Legacy puro. Portanto, suporte a Legacy exige uma etapa própria
compatível com o modo de inicialização correspondente.

O caminho CSM também não deve pressupor disponibilidade de GOP ou de
todos os protocolos UEFI. A camada de plataforma deverá detectar e expor
os recursos realmente disponíveis.

## 11. Falhas, diagnósticos e logs

`fail.c` permanece como autoridade central para detectar falhas. Nenhum

``` text
Componente que detecta a condição
          |
          v
        fail.c
          |
          v
   Core/Diagnostics
       /       \
      v         v
 Display.c   LogGen.c
```

O contrato real de integração ainda precisa ser definido a partir das
APIs existentes desses componentes.

### 11.3 Requisitos

-   Preservar a origem da falha.
-   Preservar código e severidade.
-   Permitir diagnóstico durante inicialização.
-   Permitir diagnóstico quando a interface gráfica não estiver
    disponível.
-   Não depender exclusivamente de Display.
-   Não transformar uma falha de apresentação em uma nova falha fatal.
-   Registrar informações suficientes para depuração.

## 14. Critérios de conclusão

O Armito não deve ser considerado integrado apenas porque compila. A
conclusão precisa ser demonstrada por testes em cada camada.

### 14.1 Core concluído

-   Todos os subsistemas possuem contratos definidos.
-   Inicialização e encerramento são previsíveis.
-   Falhas parciais não deixam o Core em estado inconsistente.
-   Dependências são resolvidas corretamente.
-   Módulos opcionais são tratados corretamente.
-   Testes automatizados cobrem estados válidos e inválidos.
-   O Core compila no ambiente-alvo.

### 14.2 Decoder concluído para uma arquitetura

-   Recebe entrada válida e delimitada.
-   Decodifica instruções suportadas.
-   Rejeita ou sinaliza instruções inválidas.
-   Produz Universal IR válido.
-   Possui testes de conformidade.

### 14.3 Backend concluído para um destino

-   Consome Universal IR validado.
-   Traduz operações suportadas.
-   Sinaliza operações não suportadas.
-   Mantém semântica funcional nas operações cobertas.
-   Possui testes comparativos.

### 14.4 Integração final concluída

-   ArmitoBoot inicia o Core.
-   Core controla os módulos.
-   Core aciona Decoder.
-   Decoder produz IR.
-   CPUToCPU recebe o IR.
-   O backend de destino processa as operações.
-   Diagnósticos e logs funcionam nos caminhos de sucesso e falha.
-   O ciclo completo é repetível e testado.

## 15. Registro de decisões e regras permanentes

1.  O projeto é chamado **Armito**.
2.  O responsável pelo projeto, nos contextos do ecossistema, é
    **SoulDotPrime**.
3.  A linguagem principal é C; Assembly pode ser usado quando
    necessário.
4.  Rust está fora do escopo atual.
5.  Core é o orquestrador central.
6.  ArmitoBoot chama Core; não chama Decoder diretamente.
7.  Core decide quando o Decoder entra em ação.
8.  Decoder trabalha com instruções da arquitetura de origem.
9.  Decoder entrega Universal IR, não código específico de um destino.
10. CPUToCPU e os backends cuidam da adaptação ao destino.
11. `fail.c` é a autoridade de detecção de falhas.
12. Core apenas instrumentaliza a apresentação e o registro das falhas.
13. `Display.c` é o caminho de apresentação visual.
14. `LogGen.c` é o caminho de geração de logs.
15. O suporte a Legacy BIOS exige um estágio próprio; um binário EFI não
    é suficiente.
16. A arquitetura deve permitir múltiplas origens e múltiplos destinos.
17. Alterações de código devem ser fornecidas como arquivos completos.
18. Cada alteração deve informar o caminho exato do arquivo.
19. Não inserir comentários dentro do código-fonte.
20. O desenvolvimento deve avançar em etapas pequenas, com confirmação
    antes da próxima alteração.

## 16. Como manter este documento

Este arquivo é a referência mestre do projeto, mas não substitui os
contratos técnicos individuais de cada módulo.

A cada avanço relevante:

1.  Atualizar o estado do roadmap.
2.  Registrar decisões arquiteturais novas.
3.  Atualizar a topologia se arquivos ou subsistemas mudarem.
4.  Registrar limitações conhecidas.
5.  Diferenciar claramente o que está implementado, o que foi testado e
    o que está apenas planejado.
6.  Não marcar uma etapa como concluída somente porque o código foi
    escrito; exigir confirmação de aplicação e, quando aplicável, teste.

estados diferentes. Um componente pode estar implementado sem estar
validado, e validado isoladamente sem estar integrado ao fluxo completo

static ArmitoCoreConfig active_config;

static ArmitoCoreStatus InitializeOptionalSubsystems(void)
{
    ArmitoCoreStatus status;

    if (active_config.enable_diagnostics) {
        status = ArmitoCoreDiagnosticsInitialize();
        if (status != ARMITO_CORE_SUCCESS)
            return status;
    }

    if (active_config.enable_monitor) {
        status = ArmitoCoreMonitorInitialize();
        if (status != ARMITO_CORE_SUCCESS)
            return status;
    }

    if (active_config.enable_scheduler) {
        status = ArmitoCoreSchedulerInitialize();
        if (status != ARMITO_CORE_SUCCESS)
            return status;
    }

    if (active_config.enable_ipc) {
        status = ArmitoCoreIPCInitialize();
        if (status != ARMITO_CORE_SUCCESS)
            return status;
    }

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreInitialize(void)
{
    if (core_initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    ArmitoCoreStatus status;

    status = ArmitoCoreConfigInitialize();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreInitPrepare();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreDispatchInitialize();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreTopologyInitialize();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreShutdownManagerInitialize();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    core_initialized = 1;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreRegisterModule(
    const ArmitoModuleDescriptor *module,
    ArmitoModuleID *assigned_id
)
{
    if (!core_initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (core_started)
        return ARMITO_CORE_INVALID_STATE;

    return ArmitoCoreRegistryRegister(module, assigned_id);
}

ArmitoCoreStatus ArmitoCoreStart(void)
{
    if (!core_initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (core_started)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    ArmitoCoreStatus status;

    status = ArmitoCoreConfigGet(&active_config);
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreTopologyBuild();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = InitializeOptionalSubsystems();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreConfigLock();
    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreInitExecute();
    if (status != ARMITO_CORE_SUCCESS) {
        ArmitoCoreConfigUnlock();
        return status;
    }

    status = ArmitoCoreInitStart();
    if (status != ARMITO_CORE_SUCCESS) {
        ArmitoCoreConfigUnlock();
        return status;
    }

    core_started = 1;

    return ARMITO_CORE_SUCCESS;
}

void ArmitoCoreShutdown(void)
{
    if (!core_initialized)
        return;

    if (ArmitoCoreShutdownManagerRequest() != ARMITO_CORE_SUCCESS)
        return;

    if (ArmitoCoreShutdownManagerExecute() != ARMITO_CORE_SUCCESS)
        return;

    ArmitoCoreShutdownManagerReset();

    core_started = 0;
    core_initialized = 0;
}

ArmitoModuleState ArmitoCoreGetModuleState(ArmitoModuleID id)
{
    if (!core_initialized)
        return ARMITO_MODULE_UNREGISTERED;

    return ArmitoCoreRegistryGetState(id);
}

ArmitoCoreStatus ArmitoCoreConfigValidate(
    const ArmitoCoreConfig *config
)
{
    if (config == NULL)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    if (config->max_modules == 0 ||
        config->max_modules > 64)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    if (config->max_dependencies == 0 ||
        config->max_dependencies > 16)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    if (config->max_tasks == 0 ||
        config->max_tasks > 64)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    if (config->max_ipc_messages == 0 ||
        config->max_ipc_messages > 64)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    if (config->max_ipc_payload == 0 ||
        config->max_ipc_payload > 256)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    if (config->enable_scheduler > 1 ||
        config->enable_ipc > 1 ||
        config->enable_monitor > 1 ||
        config->enable_diagnostics > 1)
        return ARMITO_CORE_CONFIGURATION_ERROR;

    return ARMITO_CORE_SUCCESS;

    return ARMITO_CORE_SUCCESS;
}

#define ARMITO_MAX_MODULES 64

typedef struct {
    ArmitoModuleDescriptor descriptor;
    ArmitoModuleState state;
    uint8_t registered;

static ArmitoRegistryEntry registry[ARMITO_MAX_MODULES];
static uint32_t module_count = 0;
static ArmitoModuleID next_id = 1;
static uint8_t registry_initialized = 0;

ArmitoCoreStatus ArmitoCoreRegistryInitialize(void)
{
    if (registry_initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        registry[i].registered = 0;
        registry[i].state = ARMITO_MODULE_UNREGISTERED;
    }

    module_count = 0;
    next_id = 1;
    registry_initialized = 1;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreRegistryRegister(
    const ArmitoModuleDescriptor *module,
    ArmitoModuleID *assigned_id)
{
    if (!registry_initialized || module == NULL)
        return ARMITO_CORE_INVALID_STATE;

    if (module->name == NULL ||
        module->initialize == NULL ||
        module->start == NULL)
        return ARMITO_CORE_ERROR;

    ArmitoCoreConfig config;

    ArmitoCoreStatus status = ArmitoCoreConfigGet(&config);

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (module_count >= config.max_modules ||
        module_count >= ARMITO_MAX_MODULES)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        if (!registry[i].registered) {
            registry[i].descriptor = *module;
            registry[i].descriptor.id = next_id;
            registry[i].state = ARMITO_MODULE_REGISTERED;
            registry[i].registered = 1;

            if (assigned_id != NULL)
                *assigned_id = next_id;

            next_id++;
            module_count++;

            return ARMITO_CORE_SUCCESS;
        }
    }

    return ARMITO_CORE_OUT_OF_RESOURCES;
}

const ArmitoModuleDescriptor *ArmitoCoreRegistryGet(ArmitoModuleID id)
{
    if (!registry_initialized || id == ARMITO_MODULE_ID_INVALID)
        return NULL;

    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        if (registry[i].registered &&
            registry[i].descriptor.id == id)
            return &registry[i].descriptor;
    }

    return NULL;
}

ArmitoModuleState ArmitoCoreRegistryGetState(ArmitoModuleID id)
{
    if (!registry_initialized)
        return ARMITO_MODULE_UNREGISTERED;

    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        if (registry[i].registered &&
            registry[i].descriptor.id == id)
            return registry[i].state;
    }

    return ARMITO_MODULE_UNREGISTERED;
}

ArmitoCoreStatus ArmitoCoreRegistrySetState(
    ArmitoModuleID id,
    ArmitoModuleState state)
{
    if (!registry_initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        if (registry[i].registered &&
            registry[i].descriptor.id == id) {
            registry[i].state = state;
            return ARMITO_CORE_SUCCESS;
        }
    }

    return ARMITO_CORE_ERROR;
}

uint32_t ArmitoCoreRegistryCount(void)
{
    return module_count;
}

void ArmitoCoreRegistryReset(void)
{
    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        registry[i].registered = 0;
        registry[i].state = ARMITO_MODULE_UNREGISTERED;
    }

    module_count = 0;
    next_id = 1;
    registry_initialized = 0;

typedef struct {
    ArmitoModuleID module_id;
    ArmitoModuleID dependencies[ARMITO_MAX_DEPENDENCIES];
    uint32_t dependency_count;
} ArmitoDependencyEntry;

static ArmitoDependencyEntry dependency_table[ARMITO_MAX_MODULES];
static uint32_t entry_count = 0;
static uint8_t initialized = 0;

ArmitoCoreStatus ArmitoCoreDependencyInitialize(void)
{
    if (initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        dependency_table[i].module_id = ARMITO_MODULE_ID_INVALID;
        dependency_table[i].dependency_count = 0;

        for (uint32_t j = 0; j < ARMITO_MAX_DEPENDENCIES; j++)
            dependency_table[i].dependencies[j] = ARMITO_MODULE_ID_INVALID;
    }

    entry_count = 0;
    initialized = 1;

    return ARMITO_CORE_SUCCESS;
}

static ArmitoDependencyEntry *FindEntry(ArmitoModuleID module_id)
{
    for (uint32_t i = 0; i < entry_count; i++) {
        if (dependency_table[i].module_id == module_id)
            return &dependency_table[i];
    }

    return NULL;
}

ArmitoCoreStatus ArmitoCoreDependencyAdd(
    ArmitoModuleID module_id,
    ArmitoModuleID dependency_id)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (module_id == ARMITO_MODULE_ID_INVALID ||
        dependency_id == ARMITO_MODULE_ID_INVALID ||
        module_id == dependency_id)
        return ARMITO_CORE_ERROR;

    if (ArmitoCoreRegistryGet(module_id) == NULL ||
        ArmitoCoreRegistryGet(dependency_id) == NULL)
        return ARMITO_CORE_ERROR;

    ArmitoCoreConfig config;

    ArmitoCoreStatus status = ArmitoCoreConfigGet(&config);

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    ArmitoDependencyEntry *entry = FindEntry(module_id);

    if (entry == NULL) {
        if (entry_count >= ARMITO_MAX_MODULES)
            return ARMITO_CORE_OUT_OF_RESOURCES;

        entry = &dependency_table[entry_count++];
        entry->module_id = module_id;
        entry->dependency_count = 0;
    }

    for (uint32_t i = 0; i < entry->dependency_count; i++) {
        if (entry->dependencies[i] == dependency_id)
            return ARMITO_CORE_ERROR;
    }

    if (entry->dependency_count >= config.max_dependencies ||
        entry->dependency_count >= ARMITO_MAX_DEPENDENCIES)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    entry->dependencies[entry->dependency_count++] = dependency_id;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreDependencyValidate(void)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    for (uint32_t i = 0; i < entry_count; i++) {
        ArmitoDependencyEntry *entry = &dependency_table[i];

        if (ArmitoCoreRegistryGet(entry->module_id) == NULL)
            return ARMITO_CORE_DEPENDENCY_ERROR;

        for (uint32_t j = 0; j < entry->dependency_count; j++) {
            if (ArmitoCoreRegistryGet(entry->dependencies[j]) == NULL)
                return ARMITO_CORE_DEPENDENCY_ERROR;
        }
    }

    return ARMITO_CORE_SUCCESS;
}

static int Visit(
    ArmitoModuleID id,
    uint8_t *visited,
    uint8_t *active,
    ArmitoModuleID *ordered,
    uint32_t *count,
    uint32_t capacity)
{
    if (id == ARMITO_MODULE_ID_INVALID || id > ARMITO_MAX_MODULES)
        return 0;

    if (active[id])
        return 0;

    if (visited[id])
        return 1;

    active[id] = 1;

    ArmitoDependencyEntry *entry = FindEntry(id);

    if (entry != NULL) {
        for (uint32_t i = 0; i < entry->dependency_count; i++) {
            if (!Visit(
                    entry->dependencies[i],
                    visited,
                    active,
                    ordered,
                    count,
                    capacity))
                return 0;
        }
    }

    active[id] = 0;
    visited[id] = 1;

    if (*count >= capacity)
        return 0;

    ordered[(*count)++] = id;

    return 1;
}

ArmitoCoreStatus ArmitoCoreDependencyResolve(
    ArmitoModuleID *ordered_modules,
    uint32_t capacity,
    uint32_t *resolved_count)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (ordered_modules == NULL || resolved_count == NULL)
        return ARMITO_CORE_ERROR;

    *resolved_count = 0;

    ArmitoCoreStatus status = ArmitoCoreDependencyValidate();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    uint32_t total_modules = ArmitoCoreRegistryCount();

    if (total_modules > ARMITO_MAX_MODULES)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (capacity < total_modules)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    uint8_t visited[ARMITO_MAX_MODULES + 1] = {0};
    uint8_t active[ARMITO_MAX_MODULES + 1] = {0};

    for (ArmitoModuleID id = 1; id <= total_modules; id++) {
        if (ArmitoCoreRegistryGet(id) == NULL)
            return ARMITO_CORE_DEPENDENCY_ERROR;

        if (!Visit(
                id,
                visited,
                active,
                ordered_modules,
                resolved_count,
                capacity))
            return ARMITO_CORE_DEPENDENCY_ERROR;
    }

    if (*resolved_count != total_modules)
        return ARMITO_CORE_DEPENDENCY_ERROR;

    return ARMITO_CORE_SUCCESS;
}

uint32_t ArmitoCoreDependencyCount(ArmitoModuleID module_id)
{
    if (!initialized)
        return 0;

    ArmitoDependencyEntry *entry = FindEntry(module_id);

    return entry != NULL ? entry->dependency_count : 0;
}

void ArmitoCoreDependencyReset(void)
{
    for (uint32_t i = 0; i < ARMITO_MAX_MODULES; i++) {
        dependency_table[i].module_id = ARMITO_MODULE_ID_INVALID;
        dependency_table[i].dependency_count = 0;
    }

    entry_count = 0;
    initialized = 0;
}

static uint32_t initialized_count = 0;
static uint32_t module_count = 0;

static uint8_t prepared = 0;
static uint8_t executed = 0;
static uint8_t started = 0;


ArmitoCoreStatus ArmitoCoreInitPrepare(void)
{
    if (prepared)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    ArmitoCoreStatus status;

    status = ArmitoCoreRegistryInitialize();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    status = ArmitoCoreDependencyInitialize();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    initialized_count = 0;
    module_count = 0;

    prepared = 1;

    return ARMITO_CORE_SUCCESS;
}


ArmitoCoreStatus ArmitoCoreInitExecute(void)
{
    if (!prepared)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (executed)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    module_count = ArmitoCoreRegistryCount();

    if (module_count > ARMITO_INIT_MAX_MODULES)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (module_count == 0) {
        executed = 1;
        return ARMITO_CORE_SUCCESS;
    }

    uint32_t resolved_count = 0;

    ArmitoCoreStatus status =
        ArmitoCoreDependencyResolve(
            initialization_order,
            ARMITO_INIT_MAX_MODULES,
            &resolved_count
        );

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (resolved_count != module_count)
        return ARMITO_CORE_DEPENDENCY_ERROR;

    for (uint32_t i = 0; i < resolved_count; i++) {

        ArmitoModuleID id = initialization_order[i];

        const ArmitoModuleDescriptor *module =
            ArmitoCoreRegistryGet(id);

        if (module == NULL)
            return ARMITO_CORE_ERROR;

        status = ArmitoCoreRegistrySetState(
            id,
            ARMITO_MODULE_INITIALIZING
        );

        if (status != ARMITO_CORE_SUCCESS)
            return status;

        status = module->initialize();

        if (status != ARMITO_CORE_SUCCESS)
            return status;

        status = ArmitoCoreRegistrySetState(
            id,
            ARMITO_MODULE_INITIALIZED
        );

        if (status != ARMITO_CORE_SUCCESS)
            return status;

        initialized_count++;
    }

    executed = 1;

    return ARMITO_CORE_SUCCESS;
}


ArmitoCoreStatus ArmitoCoreInitStart(void)
{
    if (!executed)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (started)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    for (uint32_t i = 0; i < module_count; i++) {

        ArmitoModuleID id = initialization_order[i];

        const ArmitoModuleDescriptor *module =
            ArmitoCoreRegistryGet(id);

        if (module == NULL)
            return ARMITO_CORE_ERROR;

        ArmitoCoreStatus status = module->start();

        if (status != ARMITO_CORE_SUCCESS)
            return status;

        status = ArmitoCoreRegistrySetState(
            id,
            ARMITO_MODULE_RUNNING
        );

        if (status != ARMITO_CORE_SUCCESS)
            return status;
    }

    started = 1;

    return ARMITO_CORE_SUCCESS;
}


void ArmitoCoreInitShutdown(void)
{
    for (uint32_t i = initialized_count; i > 0; i--) {

        ArmitoModuleID id = initialization_order[i - 1];

        const ArmitoModuleDescriptor *module =
            ArmitoCoreRegistryGet(id);

        if (module == NULL)
            continue;

        if (module->shutdown != NULL)
            module->shutdown();

        ArmitoCoreRegistrySetState(
            id,
            ARMITO_MODULE_STOPPED
        );
    }

    initialized_count = 0;
    module_count = 0;

    started = 0;
    executed = 0;
    prepared = 0;

ArmitoCoreStatus ArmitoCoreTopologyInitialize(void)
{
    if (initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    topology_count = 0;
    built = 0;

    for (uint32_t i = 0; i < ARMITO_TOPOLOGY_MAX_MODULES; i++)
        topology_order[i] = ARMITO_MODULE_ID_INVALID;

    initialized = 1;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreTopologyBuild(void)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    topology_count = 0;
    built = 0;

    uint32_t registered_count = ArmitoCoreRegistryCount();

    if (registered_count > ARMITO_TOPOLOGY_MAX_MODULES)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (registered_count == 0) {
        built = 1;
        return ARMITO_CORE_SUCCESS;
    }

    ArmitoCoreStatus status =
        ArmitoCoreDependencyResolve(
            topology_order,
            ARMITO_TOPOLOGY_MAX_MODULES,
            &topology_count
        );

    if (status != ARMITO_CORE_SUCCESS) {
        topology_count = 0;
        return status;
    }

    if (topology_count != registered_count) {
        topology_count = 0;
        return ARMITO_CORE_DEPENDENCY_ERROR;
    }

    built = 1;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreTopologyGetOrder(
    ArmitoModuleID *ordered_modules,
    uint32_t capacity,
    uint32_t *module_count)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (!built)
        return ARMITO_CORE_INVALID_STATE;

    if (ordered_modules == NULL || module_count == NULL)
        return ARMITO_CORE_ERROR;

    if (capacity < topology_count)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    for (uint32_t i = 0; i < topology_count; i++)
        ordered_modules[i] = topology_order[i];

    *module_count = topology_count;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreTopologyGetPosition(
    ArmitoModuleID module_id,
    uint32_t *position)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    if (!built)
        return ARMITO_CORE_INVALID_STATE;

    if (module_id == ARMITO_MODULE_ID_INVALID || position == NULL)
        return ARMITO_CORE_ERROR;

    for (uint32_t i = 0; i < topology_count; i++) {
        if (topology_order[i] == module_id) {
            *position = i;
            return ARMITO_CORE_SUCCESS;
        }
    }

    return ARMITO_CORE_ERROR;
}

void ArmitoCoreTopologyReset(void)
{
    for (uint32_t i = 0; i < ARMITO_TOPOLOGY_MAX_MODULES; i++)
        topology_order[i] = ARMITO_MODULE_ID_INVALID;

    topology_count = 0;
    built = 0;
    initialized = 0;
}

static ArmitoCoreStatus ArmitoCoreMonitorCheckEnabled(void)

    uint8_t enabled = 0;

    ArmitoCoreStatus status =
        ArmitoCoreConfigIsFeatureEnabled(
            ARMITO_CORE_FEATURE_MONITOR,
            &enabled
        );

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    return enabled ? ARMITO_CORE_SUCCESS : ARMITO_CORE_NOT_SUPPORTED;

    if (initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreMonitorCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    initialized = 1;

    return ARMITO_CORE_SUCCESS;

ArmitoCoreStatus ArmitoCoreMonitorGetModuleState(
    ArmitoModuleID module_id,
    ArmitoModuleState *state)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreMonitorCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (state == NULL || module_id == ARMITO_MODULE_ID_INVALID)
        return ARMITO_CORE_ERROR;

    if (ArmitoCoreRegistryGet(module_id) == NULL)
        return ARMITO_CORE_ERROR;

    *state = ArmitoCoreRegistryGetState(module_id);

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreMonitorGetReport(
    ArmitoCoreMonitorReport *report)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreMonitorCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (report == NULL)
        return ARMITO_CORE_ERROR;

    report->total = 0;
    report->registered = 0;
    report->initializing = 0;
    report->initialized = 0;
    report->running = 0;
    report->stopped = 0;
    report->unregistered = 0;

    uint32_t count = ArmitoCoreRegistryCount();

    for (ArmitoModuleID id = 1; id <= count; id++) {
        if (ArmitoCoreRegistryGet(id) == NULL)
            continue;

        ArmitoModuleState state =
            ArmitoCoreRegistryGetState(id);

        report->total++;

        switch (state) {
            case ARMITO_MODULE_REGISTERED:
                report->registered++;
                break;

            case ARMITO_MODULE_INITIALIZING:
                report->initializing++;
                break;

            case ARMITO_MODULE_INITIALIZED:
                report->initialized++;
                break;

            case ARMITO_MODULE_RUNNING:
                report->running++;
                break;

            case ARMITO_MODULE_STOPPED:
                report->stopped++;
                break;

            default:
                report->unregistered++;
                break;
        }
    }

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreMonitorIsHealthy(
    uint8_t *healthy)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreMonitorCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (healthy == NULL)
        return ARMITO_CORE_ERROR;

    ArmitoCoreMonitorReport report;

    status = ArmitoCoreMonitorGetReport(&report);

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    *healthy = (
        report.total > 0 &&
        report.initializing == 0 &&
        report.registered == 0 &&
        report.stopped == 0 &&
        report.unregistered == 0 &&
        report.running == report.total
    );

    return ARMITO_CORE_SUCCESS;
}

{
    initialized = 0;

#ifndef ARMITO_CORE_SCHEDULER_H
#define ARMITO_CORE_SCHEDULER_H

#include "Includes/Core.h"

#define ARMITO_SCHEDULER_MAX_TASKS 64

typedef uint32_t ArmitoTaskID;

#define ARMITO_TASK_ID_INVALID 0

typedef enum {
    ARMITO_TASK_PENDING = 0,
    ARMITO_TASK_EXECUTING,
    ARMITO_TASK_COMPLETED,
    ARMITO_TASK_FAILED
} ArmitoTaskState;

typedef ArmitoCoreStatus (*ArmitoTaskFunction)(void *context);

typedef struct {
    ArmitoTaskID id;
    ArmitoModuleID module_id;
    ArmitoModulePriority priority;
    ArmitoTaskFunction execute;
    void *context;
} ArmitoTaskDescriptor;

ArmitoCoreStatus ArmitoCoreSchedulerInitialize(void);

ArmitoCoreStatus ArmitoCoreSchedulerSubmit(
    const ArmitoTaskDescriptor *task,
    ArmitoTaskID *assigned_id
);

    ArmitoTaskID *executed_task
);

ArmitoCoreStatus ArmitoCoreSchedulerGetTaskState(
    ArmitoTaskID task_id,
    ArmitoTaskState *state
);

void ArmitoCoreSchedulerReset(void);

#endif#include "Includes/CoreScheduler.h"
#include "Registry/Includes/CoreRegistry.h"
#include "Config/Includes/CoreConfig.h"

typedef struct {
    ArmitoTaskDescriptor descriptor;
    ArmitoTaskState state;
    uint8_t registered;
} ArmitoSchedulerEntry;

static ArmitoSchedulerEntry task_table[ARMITO_SCHEDULER_MAX_TASKS];
static uint32_t task_count = 0;
static ArmitoTaskID next_task_id = 1;
static uint8_t initialized = 0;

static ArmitoCoreStatus ArmitoCoreSchedulerCheckEnabled(void)
{
    uint8_t enabled = 0;

    ArmitoCoreStatus status =
        ArmitoCoreConfigIsFeatureEnabled(
            ARMITO_CORE_FEATURE_SCHEDULER,
            &enabled
        );

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    return enabled ? ARMITO_CORE_SUCCESS : ARMITO_CORE_NOT_SUPPORTED;
}

ArmitoCoreStatus ArmitoCoreSchedulerInitialize(void)
{
    if (initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreSchedulerCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    for (uint32_t i = 0; i < ARMITO_SCHEDULER_MAX_TASKS; i++) {
        task_table[i].registered = 0;
        task_table[i].state = ARMITO_TASK_PENDING;
    }

    task_count = 0;
    next_task_id = 1;
    initialized = 1;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreSchedulerSubmit(
    const ArmitoTaskDescriptor *task,
    ArmitoTaskID *assigned_id)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreSchedulerCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (task == NULL || task->execute == NULL)
        return ARMITO_CORE_ERROR;

    if (task->module_id == ARMITO_MODULE_ID_INVALID)
        return ARMITO_CORE_ERROR;

    if (ArmitoCoreRegistryGet(task->module_id) == NULL)
        return ARMITO_CORE_ERROR;

    if (task->priority < ARMITO_PRIORITY_CRITICAL ||
        task->priority > ARMITO_PRIORITY_LOW)
        return ARMITO_CORE_ERROR;

    ArmitoCoreConfig config;

    status = ArmitoCoreConfigGet(&config);

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (task_count >= config.max_tasks ||
        task_count >= ARMITO_SCHEDULER_MAX_TASKS)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (next_task_id == ARMITO_TASK_ID_INVALID)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    for (uint32_t i = 0; i < ARMITO_SCHEDULER_MAX_TASKS; i++) {
        if (!task_table[i].registered) {
            task_table[i].descriptor = *task;
            task_table[i].descriptor.id = next_task_id;
            task_table[i].state = ARMITO_TASK_PENDING;
            task_table[i].registered = 1;

            if (assigned_id != NULL)
                *assigned_id = next_task_id;

            next_task_id++;
            task_count++;

            return ARMITO_CORE_SUCCESS;
        }
    }

    return ARMITO_CORE_OUT_OF_RESOURCES;
}

ArmitoCoreStatus ArmitoCoreSchedulerExecuteNext(
    ArmitoTaskID *executed_task)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreSchedulerCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    ArmitoSchedulerEntry *selected = NULL;

    for (uint32_t i = 0; i < ARMITO_SCHEDULER_MAX_TASKS; i++) {
        if (!task_table[i].registered ||
            task_table[i].state != ARMITO_TASK_PENDING)
            continue;

        if (selected == NULL ||
            task_table[i].descriptor.priority <
            selected->descriptor.priority)
            selected = &task_table[i];
    }

    if (selected == NULL)
        return ARMITO_CORE_INVALID_STATE;

    if (ArmitoCoreRegistryGetState(selected->descriptor.module_id) !=
        ARMITO_MODULE_RUNNING)
        return ARMITO_CORE_INVALID_STATE;

    selected->state = ARMITO_TASK_EXECUTING;

    status = selected->descriptor.execute(selected->descriptor.context);

    if (status == ARMITO_CORE_SUCCESS)
        selected->state = ARMITO_TASK_COMPLETED;
    else
        selected->state = ARMITO_TASK_FAILED;

    if (executed_task != NULL)
        *executed_task = selected->descriptor.id;

    return status;
}

ArmitoCoreStatus ArmitoCoreSchedulerGetTaskState(
    ArmitoTaskID task_id,
    ArmitoTaskState *state)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreSchedulerCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (task_id == ARMITO_TASK_ID_INVALID || state == NULL)
        return ARMITO_CORE_ERROR;

    for (uint32_t i = 0; i < ARMITO_SCHEDULER_MAX_TASKS; i++) {
        if (task_table[i].registered &&
            task_table[i].descriptor.id == task_id) {
            *state = task_table[i].state;
            return ARMITO_CORE_SUCCESS;
        }
    }

    return ARMITO_CORE_ERROR;
}

void ArmitoCoreSchedulerReset(void)
{
    for (uint32_t i = 0; i < ARMITO_SCHEDULER_MAX_TASKS; i++) {
        task_table[i].registered = 0;
        task_table[i].state = ARMITO_TASK_PENDING;
    }

    task_count = 0;
    next_task_id = 1;
    initialized = 0;
}

#ifndef ARMITO_CORE_IPC_H

typedef struct {
    ArmitoIPCMessage message;
    uint64_t sequence;
    uint8_t occupied;
} ArmitoIPCEntry;

static ArmitoIPCEntry message_queue[ARMITO_IPC_MAX_MESSAGES];
static ArmitoMessageID next_message_id = 1;
static uint64_t next_sequence = 1;
static uint32_t pending_count = 0;
static uint8_t initialized = 0;

static ArmitoCoreStatus ArmitoCoreIPCCheckEnabled(void)
{
    uint8_t enabled = 0;

    ArmitoCoreStatus status =
        ArmitoCoreConfigIsFeatureEnabled(
            ARMITO_CORE_FEATURE_IPC,
            &enabled
        );

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    return enabled ? ARMITO_CORE_SUCCESS : ARMITO_CORE_NOT_SUPPORTED;
}

ArmitoCoreStatus ArmitoCoreIPCInitialize(void)
{
    if (initialized)
        return ARMITO_CORE_ALREADY_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreIPCCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    for (uint32_t i = 0; i < ARMITO_IPC_MAX_MESSAGES; i++) {
        message_queue[i].occupied = 0;
        message_queue[i].sequence = 0;
    }

    next_message_id = 1;
    next_sequence = 1;
    pending_count = 0;
    initialized = 1;

    return ARMITO_CORE_SUCCESS;
}

ArmitoCoreStatus ArmitoCoreIPCSend(
    ArmitoModuleID sender,
    ArmitoModuleID receiver,
    ArmitoMessageType type,
    const void *payload,
    uint32_t size,
    ArmitoMessageID *message_id
)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreIPCCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (sender == ARMITO_MODULE_ID_INVALID ||
        receiver == ARMITO_MODULE_ID_INVALID)
        return ARMITO_CORE_ERROR;

    if (ArmitoCoreRegistryGet(sender) == NULL ||
        ArmitoCoreRegistryGet(receiver) == NULL)
        return ARMITO_CORE_ERROR;

    if (size > ARMITO_IPC_MAX_PAYLOAD)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (size > 0 && payload == NULL)
        return ARMITO_CORE_ERROR;

    ArmitoCoreConfig config;

    status = ArmitoCoreConfigGet(&config);

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (size > config.max_ipc_payload)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (pending_count >= config.max_ipc_messages ||
        pending_count >= ARMITO_IPC_MAX_MESSAGES)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    if (next_message_id == ARMITO_MESSAGE_ID_INVALID ||
        next_message_id == UINT32_MAX)
        return ARMITO_CORE_OUT_OF_RESOURCES;

    for (uint32_t i = 0; i < ARMITO_IPC_MAX_MESSAGES; i++) {
        if (!message_queue[i].occupied) {
            ArmitoIPCEntry *entry = &message_queue[i];

            entry->message.id = next_message_id;
            entry->message.sender = sender;
            entry->message.receiver = receiver;
            entry->message.type = type;
            entry->message.size = size;

            if (size > 0)
                memcpy(entry->message.payload, payload, size);

            entry->sequence = next_sequence++;
            entry->occupied = 1;

            if (message_id != NULL)
                *message_id = next_message_id;

            next_message_id++;
            pending_count++;

            return ARMITO_CORE_SUCCESS;
        }
    }

    return ARMITO_CORE_OUT_OF_RESOURCES;
}

ArmitoCoreStatus ArmitoCoreIPCReceive(
    ArmitoModuleID receiver,
    ArmitoIPCMessage *message
)
{
    if (!initialized)
        return ARMITO_CORE_NOT_INITIALIZED;

    ArmitoCoreStatus status = ArmitoCoreIPCCheckEnabled();

    if (status != ARMITO_CORE_SUCCESS)
        return status;

    if (receiver == ARMITO_MODULE_ID_INVALID || message == NULL)
        return ARMITO_CORE_ERROR;

    if (ArmitoCoreRegistryGet(receiver) == NULL)
        return ARMITO_CORE_ERROR;

    ArmitoIPCEntry *selected = NULL;

    for (uint32_t i = 0; i < ARMITO_IPC_MAX_MESSAGES; i++) {
        ArmitoIPCEntry *entry = &message_queue[i];

        if (!entry->occupied || entry->message.receiver != receiver)
            continue;

        if (selected == NULL || entry->sequence < selected->sequence)
            selected = entry;
    }

    if (selected == NULL)
        return ARMITO_CORE_INVALID_STATE;

    *message = selected->message;

    selected->occupied = 0;
    selected->sequence = 0;

    if (pending_count > 0)
        pending_count--;

    return ARMITO_CORE_SUCCESS;
}

uint32_t ArmitoCoreICPPendingCount(void)
{
    if (!initialized)
        return 0;

    if (ArmitoCoreIPCCheckEnabled() != ARMITO_CORE_SUCCESS)
        return 0;

    return pending_count;
}

void ArmitoCoreIPCReset(void)
{
    for (uint32_t i = 0; i < ARMITO_IPC_MAX_MESSAGES; i++) {
        message_queue[i].occupied = 0;
        message_queue[i].sequence = 0;
    }

    next_message_id = 1;
    next_sequence = 1;
    pending_count = 0;
    initialized = 0;
}
